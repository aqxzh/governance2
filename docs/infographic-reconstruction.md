# Поэтапная замена растровых инфографик

Работа только в локальной Svelte-ветке. Исходные изображения сохраняются как эталон, React/Figma/production не изменяются. Субагенты проводят текстовую инвентаризацию и подготовку компонентов; основной агент непосредственно сравнивает изображения и проверяет результат.

## Правила

- Восстанавливаем содержание и структуру, а не масштабируем скриншот внутри нового компонента.
- Текст — Paraglide RU/KK/EN, с переносами; KK/EN остаются черновиками. HTML предпочтительнее SVG для длинного текста, таблиц и карточек. SVG — для связей, схем и графиков.
- Стандартные shadcn Vega/Zinc/Blue и semantic tokens. Не копируем абсолютную Figma-вёрстку, микрошрифт и обрезанные блоки.
- Данные сверяем с React-кодом и визуальным эталоном; неразборчивый текст отмечаем, не выдумываем. Показатели источника — демонстрационные, не подтверждённые результаты.
- Фото и видео остаются медиа. Карты-подложки и изображения интерфейсов внутри презентаций учитываем отдельно: перенос внешней презентации не означает, что вложенные скриншоты уже локализованы.
- Не изображаем работающий AI/бэкенд и не добавляем фальшивые интерактивные контролы.
- Сохраняем исходные сценарии и старые якоря. Общий renderer должен заменять изображение во всех местах применения, чтобы старый скриншот не оставался в модальном окне.
- Проверки: типы/автофиксер, unit/browser/static, сравнение на 390/768/1440, локали, no-JS и reduced motion.

## Модели и библиотеки

Проверен session-scoped `models_list`: `SuperPC/glm-5.3-flash` и `openai-codex/gpt-6-luna` поддерживают text + image по метаданным Pi; стоковый `SuperPC/glm-5.3` — только text. Лёгкое формирование инфографик поручаем Flash/Luna с явным model override; Sol/Astra — по сложности. Это metadata capability, не live-тест endpoint. Основной агент также непосредственно проверяет скриншоты.

Полностью прочитан `/home/marinadec/Downloads/unified_stack_spec.md`, редакция 3.1, особенно раздел 4. Выбор по типу:

- Обычные графики: **Chart shadcn-svelte + LayerChart**.
- Процессы/узлы с взаимодействием: **Svelte Flow (`@xyflow/svelte`)**.
- Сложная аналитика, heatmap/Sankey: **Apache ECharts**, если LayerChart недостаточен.
- Исследование сетей и графовые алгоритмы: **Cytoscape.js**; не ставим ради декоративных соединений.
- Статичная иллюстративная схема без редактора/аналитики: допустим простой SVG + Svelte и существующие shadcn-компоненты. Для первого «Было / Стало» нет ни реальных данных графа, ни потребности в редакторе; SVG не подменяет будущую библиотечную аналитику.

Библиотеки раздела 4 подключаются по потребности, не все одновременно. Перед установкой проверить актуальные версии, Svelte 5/Kit 2, SSR/prerender и локализованные подписи; клиентский canvas не должен лишать страницы содержимого без JS. Новые chart/graph зависимости пока не установлены.

## Инвентаризация субагентами

Два read-only scout-а проверили Svelte-компоненты/медиа-provenance и исходный React-код. Их выводы требуют визуального подтверждения: например, AI-советник уже восстановлен в HTML/SVG, поэтому переносить его заново первым этапом не нужно. Декоративные security-иконки не решают проблему переводимого текста и не являются приоритетным пилотом.

## Последовательность

1. Инвентаризация и два небольших векторных примера «Было / Стало».
2. Переговоры агентов и схема «событие → расчёт → интерпретация»; восстановление обоих растровых entry-points общим renderer.
3. Четыре насыщенные презентации: по одной, с отдельной сверкой вложенных скриншотов и карт.
4. Диагностические/координационные иллюстрации тематическими группами.
5. Схемы шагов и остальные материалы главной; финальный аудит всех `<img>` с текстом.

## Результат первого этапа

«Было / Стало» заменены на `SystemDiagram.svelte`, непосредственно в карточках главной, без модального окна и растрового содержания. Заголовки/accessible SVG titles используют существующие переводы Paraglide; у исходных узлов нет названий, поэтому новые подписи не добавлялись. Схема «Стало» сохраняет структуру оригинала. Связи запутанной сети — иллюстративная реконструкция, не верифицированный граф данных и не точная трассировка всех скрытых пересечений.

Draft подготовил Sol, визуальный/code-review выполнила Luna; основной агент напрямую проверил оригиналы и итоговые RU1440/KK390/EN768 screenshots. Левый вертикальный ствол нижних ветвей сохранён по оригиналу — это не обязательное центрирование оргсхемы. `pnpm verify`: 39 unit, 161 browser passed + 1 intentional skip, svelte-check 0 ошибок/0 предупреждений. `.artifacts/preview/diagrams/`: 9 сочетаний локалей/ширин, SVG не выходят за viewBox, нет page overflow/browser errors, обе схемы доступны без JavaScript. Остальные изображения и текстовые презентации этим этапом не заменены.

Готовность каждого этапа подтверждается отдельно. Инвентаризация — не утверждение, что все перечисленные изображения уже заменены.
